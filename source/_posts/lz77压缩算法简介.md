## 1. 基本思想

LZ77 是一种无损压缩算法，由 Abraham Lempel 和 Jacob Ziv 于 1977 年提出。它的核心思想是：

> 如果当前字符串之前已经出现过，就不再重复保存原文，而是保存它与历史内容之间的距离和匹配长度。

例如：

```
abc123abc123xyz
```

第二个 `abc123` 已经在前面出现，因此可以表示为：

```
abc123 + (distance=6, length=6) + xyz
```

其中：

- `distance=6`：从当前位置向前回退 6 个字节。
- `length=6`：复制 6 个字节。

LZ77 利用的是数据中的重复性。重复内容越多，压缩效果通常越好。

## 2. 滑动窗口

LZ77 不一定搜索整个历史数据，而是维护一个有限大小的滑动窗口：

```
┌───────────────┬──────────────┐
│ 已处理的历史数据 │ 尚未处理的数据 │
└───────────────┴──────────────┘
                ↑
              当前位置
```

历史部分称为搜索缓冲区，当前位置之后的内容称为前向缓冲区。

压缩器会在历史窗口中寻找与当前位置开头相同的最长字符串。

窗口越大：

- 越可能找到距离较远的重复内容。
- 压缩率可能越高。
- 匹配查找需要更多内存和计算。

窗口越小：

- 查找速度更快。
- Offset 可以用更少比特表示。
- 可能错过较远的重复内容。

## 3. LZ77 的输出形式

最基本的 LZ77 输出包含两类数据。

### Literal

没有找到合适的历史匹配时，直接保存原始字节：

```
Literal('a')
Literal('b')
Literal('c')
```

### Match

找到重复内容时，保存距离和长度：

```
Match(distance, length)
```

例如：

```
abcabcabc
```

可以表示为：

```
Literal("abc")
Match(distance=3, length=6)
```

解压器先得到 `abc`，然后从前面 3 个字节的位置复制 6 个字节，恢复出：

```
abcabcabc
```

## 4. 重叠匹配

LZ77 通常允许复制区间与目标区间重叠。

例如：

```
aaaaaaaaaa
```

可以表示为：

```
Literal('a')
Match(distance=1, length=9)
```

解压时必须从左向右复制：

```
for (int i = 0; i < length; i++) {
    output[current + i] =
        output[current - distance + i];
}
```

刚写入的字节可以立即成为后续复制的数据源：

```
a
aa
aaa
aaaa
...
aaaaaaaaaa
```

周期字符串也可以这样处理：

```
已有：abc
distance=3
length=9
```

最终得到：

```
abcabcabcabc
```

## 5. 如何寻找重复字符串

直接将当前位置与所有历史位置比较，最坏情况下可能达到平方级复杂度。实际压缩算法会使用数据结构快速寻找候选位置。

### 单哈希表

对当前位置开头的若干字节计算哈希：

```
hash("abcd") -> 最近出现位置
```

然后从候选位置继续向后比较，确定真正的匹配长度。

优点是速度快，缺点是只保存最近位置时，可能错过更早但更长的匹配。

### 哈希链

保存同一个哈希对应的多个历史位置：

```
hash("abcd") -> 100 -> 80 -> 43 -> 12
```

依次检查候选并选择更好的匹配。搜索越深，压缩率可能越高，但压缩速度越慢。

### 双哈希

同时维护短前缀和长前缀的哈希表：

```
短哈希：快速发现短匹配
长哈希：减少冲突，发现长匹配
```

这是速度和压缩率之间的折中。

### 二叉树

按照历史后缀的字典序组织候选位置。查找时根据字符串比较结果进入左子树或右子树，并记录最长公共前缀。

二叉树更适合高压缩等级，但维护成本和内存访问开销更高。

## 6. 匹配长度如何确定

哈希通常只用于找到候选位置，不代表最终匹配长度。

假设算法使用前 4 个字节计算哈希：

```
当前位置：abcdabcdefgh
历史位置：abcdabcdefX
```

前 4 字节相同后，压缩器会继续向后比较：

```
int length = 4;

while (current + length < input.length
        && input[previous + length]
             == input[current + length]) {
    length++;
}
```

因此，“4 字节哈希”只是查找入口，实际匹配长度可能是 4、10、100，甚至更长。

不同算法的最短匹配长度不同。例如 Deflate 通常允许 3 字节匹配，LZ4 通常从 4 字节匹配开始。

## 7. 找到多个匹配后如何选择

找到最长匹配并不一定意味着最终压缩结果最小，因为还要考虑 Offset 的编码成本和后续匹配。

### 贪心匹配

当前位置找到一个较好匹配后立即使用：

```
找到长度10的匹配 -> 直接选择
```

实现简单、速度快，LZ4 等高速算法常采用这种策略。

### Lazy Matching

暂时不使用当前位置的匹配，继续查看下一个位置：

```
当前位置匹配长度10
下一位置匹配长度30
```

此时可以先输出一个 Literal，再使用长度 30 的匹配。

### Optimal Parsing

使用动态规划计算编码成本：

```
dp[i] = 编码到位置 i 所需的最少比特数
```

每个位置可以选择：

```
输出Literal
使用某个Match
```

这种方法压缩率更高，但压缩过程明显更慢。

## 8. 压缩和解压伪代码

简化的压缩过程：

```
while (current < input.length) {
    Match match = findBestMatch(input, current);

    if (match.length >= MIN_MATCH) {
        emitMatch(match.distance, match.length);
        current += match.length;
    } else {
        emitLiteral(input[current]);
        current++;
    }
}
```

简化的解压过程：

```
for (Token token : tokens) {
    if (token.isLiteral()) {
        output.write(token.literal);
    } else {
        int start = output.position() - token.distance;

        for (int i = 0; i < token.length; i++) {
            output.write(output.get(start + i));
        }
    }
}
```

解压不需要重新搜索重复串，只需要执行 Literal 和 Match 指令，因此通常比高等级压缩快得多。

## 9. LZ77 与现代压缩算法

LZ77 更像一种基础压缩思想，现代算法通常在其基础上增加匹配搜索和熵编码。

| 算法    | 基于 LZ77 的扩展                  |
| ------- | --------------------------------- |
| LZ4     | 简单哈希查找，强调极高速度        |
| Snappy  | Literal/Copy 指令，强调稳定低延迟 |
| Deflate | LZ77 + Huffman                    |
| Zstd    | LZ77 + Huffman + FSE              |
| Brotli  | LZ77 + 静态词典 + 上下文编码      |
| LZMA    | 大窗口 LZ77 + Range Coding        |

以 Zstd 为例，它先使用 LZ77 将数据拆成：

```
Literals：未匹配的原始字节
Sequences：Literal长度、Offset、Match长度
```

然后：

```
Literals            -> Huffman编码
长度和Offset等信息    -> FSE编码
```

LZ77 负责消除长字符串重复，熵编码负责继续压缩剩余符号。
